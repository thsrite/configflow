## 结果

| # | 结果 |
|---|---|
| P1 | 通过：Mihomo（CT 221）、OxiDNS（CT 222）、MosDNS（CT 223）都走完 stage-only → `ready` → activate → `succeeded`；核心 PID 变化（重启）或热重载，设备上主配置的 SHA-256 等于 `config_version`，DNS 能解析。OxiDNS 第一次激活时，默认 remote 上游（DoH 1.1.1.1/8.8.8.8）在实验网不可达，DNS 检查失败后自动 `rolled_back` 并恢复旧配置（顺带覆盖了 P3 的 OxiDNS 路径）；改用 DoH-by-IP 后通过 |
| P2 | 1.8.56-go：发布成功；回滚失败后点「重新恢复」返回 405，并给出升级或设备上 `-recover-and-exit` 的手动步骤，按步骤操作后状态收敛为 `rolled_back`。1.8.29-go：stage → activate → `succeeded`。1.2.0-go（最老的 protocol-1）：上传和校验通过，但激活时 Agent 自带的 HTTP 代理握手检查（`CONNECT /` 只接受 400/403/405/407）和 Mihomo v1.19.32 不兼容，新旧配置都过不了 → `rollback_failed`。这是旧 Agent 与新内核的已知问题，不是 Go 面板的问题（O6）；升到 1.8.61 后由面板恢复，收敛为 `rolled_back` |

## 缺陷

| ID | 严重程度 | 摘要 | 状态 |
|---|---|---|---|
| D1 | 中 | 「重新恢复原配置」被 Agent 受理后面板返回 500（Python 同样），Agent 页提示「无法重新恢复」并停止跟踪，而设备实际正在恢复 | **已修**：`547662cb2`，受理时返回 202，附 `TestDeployHTTPAcceptedRecoveryIsAccepted`（负控：去掉修复后得到 500）；实验网复测 202 → `rolling_back` → `rolled_back` |
| D2 | 中 | M16：Mihomo alpha 内核上报 `alpha-<hash>`，开启 EasyTier 出站后无法生成和发布，提示还误导用户「升级或重启 Agent」 | 协调者已裁定，另派执行者 |
| D4 | **高（发布阻断）** | Docker Hub 上现有的 `thsrite/config-flow-agent:latest`（11-14 构建）配 Go 面板生成的 docker 命令，新装 Docker Agent 必然注册失败（403「安装命令已失效…」）：O9-H2（`62d4fc452`）要求首次注册带一次性凭据，旧镜像的入口脚本不认 `AGENT_<SVC>_REGISTRATION_TOKEN`，也不支持注册密钥。用当前树构建的镜像可以注册。O12/O14 都没写这个依赖 | 已报告协调者，另派执行者：Agent 镜像与面板同版本配套发布，O12/O14 写明 |
| D3 | 低 | Agent 只在连上控制器时取一次 `/version`；快速替换内核并重启（中间没有轮询失败）后，会继续上报旧版本，直到 Agent 重启 | Agent 侧后续任务（`domain_discovery.go` 的 `pollLoop`/`fetchVersion`） |

## 观察

- O1：GitHub 在实验网时快时慢（同一天 9 秒到超时都有）。面板下载 ASN 偶尔 404 或超时，重试成功。原始错误里显示 Go 类型名 `*rulefetch.FetchError`，Python 显示的是 `HTTPError`，属于「不追求」的异常文本类。
- O2：默认模板带 `external-ui`。设备上没有 `ui` 目录且 GitHub 不通时，Mihomo 在热重载时下载 UI，会阻塞到 Agent 的 60 秒超时，然后改为重启（发布仍然成功，只是慢 60 秒）。Python 生成的模板相同。
- O3：实验网的明文 DNS（:53）原本会经家里路由器被劫持到生产 DNS。本批在实验网自有的 `inet cfgt` 表里加了 DNAT，把发往实验网外的 :53 交给 CT 220 上的实验解析器（mosdns，上游 DoH-by-IP），并丢弃 :853。实验 DNS 查询不再进入生产。
- O4：安装器的核心下载地址写死为 GitHub。实验网下载失败时，在面板 CT 上放了官方文件镜像（在 .64 下载，SHA256 与安装器固定值一致），客户机 PATH 前放 curl/wget 包装把 release 地址映射过去；脚本的 SHA256 校验照常执行。
- O5：1.8.56 的手动恢复提示写在事件里；之后的一次轮询会用 Agent 状态覆盖 `message`，提示只留在事件列表中（Python 相同）。事件中的 URL（包括 `http://127.0.0.1:9091/version`）会显示成「[下载地址已隐藏]」，也与 Python 相同。
- O6：1.2.0-go 的代理握手检查不兼容 Mihomo v1.19.32，见 P2。
- O7：SIGTERM 时正在进行的发布请求返回 500，并记一条 ERROR「Exception on …/push-config: context canceled」。符合「关停后不再写记录」的设计，只是日志里有噪声。

## 没有覆盖到的

- Surge 旧发布路径：实验网没有 macOS/iOS，只有 fake 覆盖，留给维护者切换时用自己的设备验证。
- MosDNS 的强制回滚失败和旧版 Agent：只在 Mihomo 上做（Agent 代码对三种服务相同）。
- 真正的旧版安装布局：旧 Agent 是在当前安装上替换二进制模拟的（与 L1 相同）。
- Docker 的 compose/AIO/HA 方式：只测了 docker run（mihomo，host 网络）。compose 和 HA 在 L1 已测；它们同样依赖新镜像（D4）。
