## 决策与实现

维护者批准：开启登录时，首次注册须注册密钥、面板 JWT 或短期一次性凭据；未开登录维持原有策略。协调者另行批准用 repo system 事务代替 gateway_installation 独立 JSON 文件，并要求哈希持久化、100 个上限、typed model。

- `model.AgentRegistrationSession` / `system.agent_registration_sessions` 是 Go 原生新字段（D2/O12，Python 无此字段）。仅存 SHA-256 digest、绑定身份和 expires；随机凭据为 crypto/rand 32 bytes，base64url 43 字符。恒时比较固定长度 SHA-256 值。
- 发号用 `repo.Update` 保存私有会话，不推进用户配置的 system revision（与独立 gateway 会话文件同语义）；消费与 Agent 更新仍在同一 `repo.UpdateSystem` 事务。
- 24h TTL 与 gateway_installation 相同；每次生成/成功注册懒清理过期项。最多 100 个未消费的**服务身份**，一批多服务超限则全部拒绝，不挤掉未过期凭据。中文 503 说明原因。
- 在同一个 `repo.UpdateSystem` 事务内检查首次注册、验证并删除会话、插入 Agent；没有跨文件提交/重放窗口。失败事务不会消费，重启不依赖内存 map。删除 Agent 后也没有可复用的会话。备份导出/导入丢弃短期会话，不能通过恢复旧备份复活凭据。
- 普通 Shell 单服务、Shell AIO、Docker Compose/run（包括普通 HA prepare 路径）都自动携带凭据。每个服务独立一个，绑定 name/service_type/port/deployment_method/profile；显式 Agent IP 也匹配请求中原始 host（保持原有 Docker/loopback 回退逻辑），端口复用同一 renderer 转换器。匿名 GET install-script 仍是无授权模板；面板 JWT 请求同一 API 才会生成凭据。core-install-command 仅装核心，无注册凭据需求。
- Agent Go 客户端从配置带上 `registration_token` / `registration_key`，成功持久化 Agent token 后移除 bootstrap 字段，保存失败恢复内存字段。Docker 入口读取每服务 `AGENT_<SERVICE>_REGISTRATION_TOKEN` 和可选 `AGENT_REGISTRATION_KEY`；已有 token 时不恢复旧 bootstrap 字段。
- `frontend/src/views/Agents.vue` 的 Shell 走 `agentsAPI.createInstallCommand`，Docker 走带 JWT 的 docker-agent-compose/run，均无需协议或 UI 改动。`doc/guide/agent-install.md` 与 `doc/manual/agents.md` 已更新安装说明和截图说明；截图布局未变，要求复制当前命令、不得公开临时凭据。
- installer fingerprint 加入已修改的 cli-output.sh，旧快照链接按既有 StaleScript 逻辑失效，避免旧无凭据脚本继续流通。

## 问题类与避免方式

| 类别 | 防护 / 验证 |
|---|---|
| 匿名注册读默认 profile 的完整配置 | 登录开启时未带三种授权之一返回 403 中文恢复提示；未登录+显式全局注册密钥仍保持原锁定，匿名生成模板不发号；原 o9repro 转为无 tag 正式回归，匿名无 token/无记录，合法 JWT 注册后仍能凭 Agent token 读含 synthetic secret 的配置 |
| 注册密钥/JWT 越过已有 Agent 归属 | 已有身份仍在注册事务内恒时核对自己的 token；密钥/JWT 不接管；附带有效 bootstrap proof 时仍消费，过期 proof 不阻断已有身份；密钥轮换后 Agent 自身 token 仍可重注册和心跳，原配置/升级路由未改 |
| 过期、错误、重复使用、并发/崩溃重放 | TTL 边界、错误值、同一凭据两个真实 HTTP 并发请求一成一拒；重开仓库后只兑现一次；删除旧记录不能恢复；失败注册仍可重试 |
| 凭据用于另一设备/服务/profile | 精确绑定身份；wrong host/name/service/port/method/profile 均拒绝；首次成功后第二地址拒绝；AIO/Docker 各服务独立凭据 |
| 凭据泄露到存储、错误、日志或通知 | 主库仅 hash；注册日志/通知白名单经 shared redact 对本次凭据脱敏，通用错误也按本次 secrets 脱敏；Shell cf_redact 新增两个 credential 字段；生成响应和脚本下载 no-store；真实 Docker writer 不打印凭据 |
| 发号无限增长 | 100 身份上限、24h 清理、原子批量生成；命令存储失败可能留下未消费 hash，仍计入上限并按 TTL 回收，不放宽授权 |
| 关机后写入 / 请求断连丢写 | owner 入口 Detach 后查 ctx.Err，事务内/提交前再查；真实 Runtime.Start/BindRequest/Shutdown 用例确认关机后发号与注册均不写，单纯 request cancel 后注册仍完成 |
| 旧数据兼容 / N8 | typed 字段与共享保留 codec；仓库只扩展精确 system 字段白名单，不扩散为自由字典；旧数据缺字段可读；备份不携带短期会话 |

边界：一次性凭据本质上是 bearer capability。未指定 IP 时，不能区分首次使用前被盗且完整冒用相同身份的机器；客户端上报 host 也不构成硬件证明。已使用的凭据对任意第二台机器都失效，显式不同 host 的请求在首次使用前也拒绝。文档说明命令保密、及时执行；此方案不声称硬件/远程机器证明。

## 差分

- 注册历史成功 corpus 两侧均带面板 JWT，保留既有 Agent token 的失败/成功样例；匿名新拒绝由正式安全回归覆盖，没有泛化忽略状态码或错误消息。
- 安装脚本只移除新增 JSON `registration_token` 的精确 43 字符 base64url 字段，Docker 只移除 `AGENT_(MIHOMO|MOSDNS|OXIDNS)_REGISTRATION_TOKEN` 的精确环境行；CLI redactor 只逆转两个固定新增字段枚举。其余脚本/JSON/YAML 仍比较。
- 新 no-store 只在对应生成内容携带凭据时归一化，其他 header 保持严格。core-install-script 仅逆转固定 CLI redactor 新字段，不移除其既有 no-store。Go/Python normalizer 有 malformed token、unknown field、其他路径、其他内容的负控。
- Installer 随机差分每个独立随机生成请求前清理**测试夹具**里的新会话，避免 100 上限把与注册无关的旧随机语料变为资源上限测试；生产上限用独立真实用例断言。
