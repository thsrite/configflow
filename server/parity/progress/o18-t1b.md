# O18 T1b — Agent/部署/HA/IPv6/规则同步/DNS 联动记录改普通结构体（2026-11-22）

分支 `go-o18-t1b`（rebase 到 go@44424c19f，batch-31）。为避免 batch-31 的 HA 自动补完改动与多个提交反复冲突，本任务的提交压成一个
（原逐步提交保留在本地分支 `o18-t1b-backup`）。沿用 T1a 裁定：宽松读存储、严格输入、未知成员丢弃并告警、只写值变了的行、`enabled:null` 读作关。

## 做了什么
- model：`agents.go/agentdeploy.go/agentha.go/agentrulesync.go/agentfollow.go/registration.go` 全部类型去掉 Raw/Fields/MemberJSON/SetJSON/Clear，
  成为普通结构体（plainRecord + 宽松 `UnmarshalJSON` + `marshalPlain`）；嵌套解码经 `plainWire` 用外层解码器（告警路径保留）。
  batch-31 新增的 `HAAutoComplete`、`HAAutoCompleteWatch` 同样处理（`heartbeats/healthy` 改 `OrderedMap`）。
- `OrderedMap[V]`（ordered.go）：用户数据作键的对象保持插入序，写时复制，无原字节；`Clone`、`SetStoredMember`、`ZeroMember`、
  `DecodeInputMember`；`EncodeMember` 返回 `json.RawMessage`；`IssueUnder` 认 `{*}` 路径。
- `model.Number`：心跳指标数字保留原字面量（uint64 计数、小数速率）。
- 开关字段错类型按 flag-truthiness 取真值并告警（Python 多数 `get()` 真值语义；规则同步 `is True` 处为已接受差异）。
- agents/*、api/agents、deploy、dnsha、dnsfollow、ipv6、monitor、rulesync、upgrades、gateway、routers、installer、notifications 等调用方
  改读类型化字段；删掉“原值证据”判断（storedText/storedAbsent/sameStoredJSON/agentIDProven 原值版/EntryValid 等）。
- `agents.DeploymentReply`：设备回复 = 类型化视图 + 原样成员（capabilities、content、listener 等未声明成员照常透传），预留结果带 `existing`。
- 协议输入（注册、编辑、部署回执、设备回复）先 `ValidJSON`，拒绝重复成员名；编辑严格（「`<成员> 类型不正确`」），注册/回执/心跳宽松。
- `copyAgent`/`copyDeployment` 改为 `model.Clone`（普通深拷贝）；读借用约定不变（OrderedMap 写时复制，浅拷贝改顶层/映射不写穿）。

## 成员表（写出规则）

  `AgentUpgrade.started_at/updated_at`、`HAJournal/HAPublicationSummary.active_agent_id`（无时写 `null`，Python 接口返回该成员）。
