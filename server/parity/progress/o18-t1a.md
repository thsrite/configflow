# O18 T1a — model 换普通 Go 结构体·第一步（完成，2026-11-22）

分支 `go-o18-t1a`（rebase 到 go@77c4c4538）。裁定：Q1 Python 建档总写的成员始终写出、可选成员 omitzero；
Q2-A 输入严格解码、形状错误查表保持 Python 文案；`*bool` 显式 null 读作关；`_revision` 暂留 `model.Int`。

## 做了什么
- `model/stored.go`：encoding/json/v2 存储解码 `DecodeStored`/`DecodeStoredMember`（宽松叶子：错类型 → 零值 + FieldIssue；
  整数接受 60/60.0/6e1/"60"；文本接受数字原文；`*bool` null → false；列表/对象/普通记录类型不符 → 零值 + issue；
  尚未迁移的记录当叶子；它们的列表里有一个元素被拒绝 → 整个列表零值 + 一个 issue，与原 R5 粒度一致）。
  普通记录的未知成员 → `IssueUnknown`（按 Go 类型遍历 JSON，T1b 直接可用）。v2 解出的切片 cap==len（R2 借用约定）。
  严格输入 `DecodeInput`/`SetJSON`/`DecodeDocument`：类型不符 → `*MemberTypeError{Record,Member,Value}`，对象/列表成员给 null 也算，
  `Int` 不接受字符串。编码 `EncodeMembers`/`EncodeMember`/`marshalPlain` 用 model 自己的编码器（旧记录不再被二次解析）。
- `model/document.go`：Document（`SchemaVersion`、System、Shared、`Profiles`）、Profile、Shared、System 为普通结构体；
  删掉 Root/Order/Raw/Fields；`Profile.SetStoredKey/Key`；旧版 `rules/rule_sets` 声明为原始 JSON 成员（`LegacyRuleList`，生成器仍读）。
  记录的 `UnmarshalJSON` 是宽松的（存储/回执/夹具；非对象仍拒绝），输入走严格接口。
- `repo/model_rows.go`：逐行解码进字段（不再拼整份文档）、逐成员编码（不再回填原字节）；未知行汇总告警一次并在下次提交删除；
  `keepUnchangedRows`：提交只写类型化值在本事务里改变的行（与 base 快照的 Go 编码比较；未改的行保留库里文本与位置），
  所以 Python 写的行、宽松读入的行、旧记录的行只在值改变时才改写。
- `repo/input_errors.go`：`inputError`（事务、导入入口）把 `MemberTypeError`/`MissingSectionError` 转 400，文案查表复用现有校验函数；
  `checkDocumentInput`：整份导入的必需成员、system 多余成员、配置空间的共享资源副本/resource_refs（Python 文案）。
- 安全：`Repository.SystemSettingsDamaged`：`system_config` 整体不是对象时 MCP、配置令牌校验拒绝，启动令牌维护不改写（否则宽松零值会变匿名访问）。
- 客户端导入：profile 结果以 JSON 成员对象传递（只应用导入器给出的成员）；shared 结果严格解码。
- 测试改比较值；Python/Flask 对照里因裁定而变的用例写明原因；pyref 只重录 metadata（条目逐字节相同）；o10t2 参考语料只有 Document/Config 行变化。
- 新守卫 `repo.TestPlainRecordsDeclareEveryStoredMember`（RejectUnknownMembers 等价：Python 参考文档、新库导出里的顶层成员都必须声明）。

## 结果
- 生产快照（.64 私有副本，探针未提交、副本已删）：T1a 层 0 个类型问题、0 个未知成员；整份按 Go 改写后再加载，值完全相同；
  改写前后 0 行字节变化（null→缺失 0 处：40 个 null 指针都在尚未迁移的嵌套记录里，T1b 处理）；一次改名提交只写 1 行。
  `TestStoredRoundTrip` 私有快照模式（含真实 Python ProfileRepository 读 Go 写的库）通过。
- 性能（.64，生产快照，model 层）：冷加载 45.3 ms/71.2 MB → 28.4 ms/41.0 MB；一次写入 8.8 ms/17.0 MB → 5.3 ms/11.7 MB。
  冷加载剩余成本里 `system.agents` 一行占 22.2 ms/35.3 MB（Agent 记录，T1b），其余各行合计约 6 ms/6 MB；≤5 ms/≤5 MB 要等 T1b/T1c。
- o10perf（.64，Go-only，空闲 5 min + 每路由 10 次，go@77c4c4538 vs T1a）：空闲 CPU 1.79% → 1.50%，空闲分配 945 → 694 MB/min，
  空闲 RSS 165 → 158 MB，负载后 RSS 200 → 184 MB；19 条路由中位延迟总和 342 → 344 ms、分配 452 → 448 MB（持平；读路由走借用快照）。
