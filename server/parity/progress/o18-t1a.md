# O18 T1a — model 换普通 Go 结构体·第一步（进行中）

分支 `go-o18-t1a`（基于 go@4e478d651）。裁定：Q1 始终写出 Python 建档成员、可选成员 omitzero；Q2-A 输入严格解码、形状错误查表保持 Python 文案。

## 已完成
- `model/stored.go`：encoding/json/v2 存储解码（`DecodeStored`、`DecodeStoredMember`）。宽松叶子：错类型 → 零值 + FieldIssue；
  整数接受 60/60.0/6e1/"60"；文本接受数字原文；`*bool` 的显式 null 读作 false；列表/对象/普通记录类型不符 → 零值 + issue；
  尚未迁移的记录（有 UnmarshalJSON）当叶子处理，拒绝时零值 + issue。普通记录的未知成员 → `IssueUnknown`（按类型遍历，T1b 可直接用）。
  v2 解出的切片 cap==len（R2 借用约定）。严格输入：`decodeMember`/`decodeStrict`（对象/列表成员给 null 视为类型不符，Int 不接受字符串），
  错误为 `*MemberTypeError{Record, Member, Value}`。`EncodeMembers` 逐成员编码（omitzero 语义同 MarshalJSON）。
- `model/document.go`：Document/Profile/Shared/System 普通结构体；`Document` 有 `SchemaVersion`，不再有 Root/Order/Raw；`Profile.SetStoredKey/Key`；
  `Profile.Rules/RuleSets`（旧版规则列表，原始 JSON）+ `LegacyRuleList`。`DecodeDocument` 严格（导入/自有副本），缺节 → `MissingSectionError`。
  记录的 `UnmarshalJSON` 是宽松的（存储/回执/夹具），输入走 `SetJSON`/`DecodeDocument`。
- `repo/model_rows.go`：逐行解码进字段，逐成员编码；未知行告警汇总一次（路径模式 + 个数）并在下次提交删除；
  `keepUnchangedRows`：提交只写类型化值在本事务里改变了的行（未改的行保留库里原文和位置），比较的是 base 快照与新值的 Go 编码。
- `repo/input_errors.go`：`inputError` 把 `MemberTypeError`/`MissingSectionError` 转成 400 校验错误，文案查表复用现有校验函数；
  `checkDocumentInput`：整份导入的必需成员、system 多余成员、配置空间的共享资源副本/resource_refs 检查（Python 文案）。
- 客户端导入的 profile 结果改为 JSON 成员对象（只应用导入器给出的成员）。
- 测试改为比较值：model_roundtrip/sections_roundtrip/typed_roundtrip/model_rows/batch16/n811/review_n83/n85/reference（Python 校验参考经输入路径）、
  o10t2 参考语料（只有 Document/Config 相关行变化，遗留记录行逐行不变）。
