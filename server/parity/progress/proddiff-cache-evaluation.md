# proddiff Python 响应缓存评估：不实施

维护者批准评估，协调者于 2026-11-18 根据实测决定取消方案。

- 测试服务器 .64 冷跑墙钟 71.978 秒，约 **72 秒**；退出码 0，self-check PASS。
- Python 累计服务时间中，现场部分 275.289 秒，可复用部分 9.575 秒，
  **live 占 96.64%**。这是并行请求及任务的累计服务时间占比，不是墙钟占比。
- 有实际收益的可复用工作主要为 **28 个离线 generator**，预计最多节省约 10 秒；
  时钟、状态准备、副作用、日志顺序依赖及未经审计的请求仍须现场执行。

结论：proddiff 本身并非此前估计的二十分钟瓶颈；缓存收益不足以抵偿长期维护
缓存失效和现场例外名单的成本。**不做缓存**，原型 `go-proddiff-cache@6f4857c42`
不合入；不再执行 hot 或 backend 修改负控。proddiff 不新增 `--no-cache` 接口，
gate 负责人已收到取消相应接入的通知。原比较器、规则、baseline、自检保持不变。

评估期间的快照、响应及缓存仅留在测试服务器私有目录，本记录不包含其内容。
