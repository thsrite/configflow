## Native file boundaries and approved differences

- jsonstore owns native Read/Write. ProbeStore and RegionStore retain their legacy
  business objects only at the Unmarshaler adapter; no health business logic changed.
  Python source audit: JsonFileStore catches OSError/ValueError and non-object,
  ProbeStore defaults missing/non-map hosts, RegionStore defaults services/domains/
  websites, TrafficStore defaults absent/non-map days. Their read-failure behavior
  remains; non-ENOENT IO adds value-free category logging.
- metrics JSONL parseLines and legacy JSON migration use native RawMessage values,
  preserve exact valid numbers, and repair only literal NaN/Infinity/-Infinity.
  Accepted points and unknown fields survive. A JSONL containing repaired literals
  is marked for rewrite at the next flush, so it is not merely appended to.
- 4301-digit integer is now accepted; 1e400, -1e400 and 1e-400 remain exact file
  lexemes. Derived projections skip samples/counter points outside the float64
  range; raw files/points remain unchanged. HTTP tests unmarshal every derived
  result with encoding/json's ordinary float64 decoder and require 200.
- Existing null samples are missing too. Summary ignores them; all-null ->null.
  Traffic stats/trends skip points with explicit null/unrepresentable counters.
  Missing *fields* retain their established defaults; no missing-value zero fill.
- API agents seedMetrics: CPU average is exactly 2.5625=(1+3+4.25+2)/4 instead
  of Python NaN. Only that field changes in summary; the prior NaN-history→null
  and overflow-network-mean→null assertions stay explicit. Saved metrics JSONL
  compare every record structurally; only agent-odd's seeded CPU NaN is repaired.
- Core file fixture `numbers`: 5 native records rather than 4 Python records,
  explicitly asserts all 5 timestamps and complete raw numeric fields, including
  both 4300/4301-digit integers. Other read/legacy rows compare structures, not
  strings containing serialized JSON. Old goldens are untouched.
- Arithmetic fixture changes are named tables: summary 8 rows; traffic 5 rows;
  trend 2 rows. They cover null/NaN/Infinity repair and unrepresentable integers;
  unrelated full results still compare strictly against original Python goldens.
- Python rollback regression uses real MetricsHistory for both old JSON and JSONL:
  files load and save; calc_stats/get_traffic_stats raise TypeError on None. The
  24-hour retention and emergency removal of null-bearing points are in the ledger.
