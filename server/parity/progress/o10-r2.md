## 设计

- `repo.borrow(ctx, fn(document, shared))`：不在写事务、也不在 section updater（`editSystemView`）里时，
  读到的是不可变快照（缓存代、新解码的代或 `WithReadSnapshot` 锁定代），`shared=true`；否则是写方工作副本，
  借用读退回深拷贝（旧行为）。例：`oxidns.SaveSettings` 在 `Update` 回调里调 `Config`，拿到的仍是自有副本。
- `lend(record, shared)`：借用时返回记录的**浅拷贝结构体**（一次分配），所以给返回值的顶层字段赋值、
  `Set/SetJSON/Clear`（copy-on-write）、给顶层切片 append 都安全；切片元素、指针目标、嵌套记录属于快照，禁止原地改。
- `resolveConfig(..., shared)`：profile 浅拷贝；`SystemConfig`/`Backup` 结构体值拷贝；`RuleLibrary` 直接用快照切片；
  `Subscriptions/Nodes/Aggregations` 是新切片（元素浅拷贝）；**只有存在 ruleset 时** `rule_configs` 才 `slices.Clone`
  后水合（原实现在拷贝上原地水合）。借给调用方的 `ProxyGroups/RuleConfigs/Routers.Items/RuleLibrary` 做 `slices.Clip`，
  调用方 append 一定重新分配，不会写进快照的空余容量。
- 写方：`UpdateConfig`/`UpdateSharedConfigs`（事务内 `resolveConfig(..., false)`）、`PublishConfig` 不变。
  `validateProfileIn`（加载与每次写校验，逐配置空间解析后只做只读的 dialer 检查）改为借用被校验的文档，
  结果不出函数；`TestO10R2ValidationDoesNotModifyTheDocument` 固定“校验不改文档”。
- 测试 guard（`view_guard.go`）：测试二进制（`testing.Testing()`）里 `Open` 默认装 guard。每次借用读先复查最近 8 代
  借出过的快照编码，再登记当前快照；`View`/`ViewAgents` 原有的前后比较保留。默认违约动作是 panic（没有 `testing.TB`，
  只在测试二进制）；`EnableViewGuardForTest(tb, r)` 改为 `tb.Error` 并在测试结束时再查一次——repo 包 `openRepo`
  与 `httpxtest.New`（50 个 HTTP 测试包）都已启用。分配测试用 `SuspendViewGuardForTest(t)`（10 个已有分配测试加了这一行）。
- 源码门禁 `TestO10R2DeepCopiesAreExplicit`：repo 包内 `copyRecord/copyValue` 只允许出现在列出的写路径/显式拷贝函数；
  repo 包外 `Clone*`/`PublishConfig` 只允许出现在列出的调用点（每条写理由），internal/api/** 与后台循环新加深拷贝会失败；
  过期豁免也失败。

## 发现 / 决策

- `Profile` 浅拷贝保留存储节键（`Key()` 与快照一致）；旧实现经编解码后 `Key()` 回落到 `ID`。只在存储 id 畸形时有区别，
  repo 包外没有对借用 profile 调 `Key()`。
- `TestPublicResultsCannotMutateCachedDocument`、`TestReadsAndSavesNeverModifyTheCommittedDocument` 原来断言“借用读返回自有副本”，
  改成：需要改嵌套成员时用 `Clone*` / 解码副本；另加借用值只改顶层不影响快照的断言。
- 后续（不在本任务）：17 个 `PublishConfig` 调用多数只为编码 + revision，可加借用版（例如 `PublishView`），
  rule-sync deploy source、router publish snapshot 会受益；R1 合并后 `agents_view.go` 的 guard 行需保留 `activeViewGuard()`。
