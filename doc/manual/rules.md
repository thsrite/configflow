# 策略规则：按顺序决定网站怎么连接、域名怎么查询

本页目录：[先加一条规则](#先加一条规则) · [匹配来源与规则类型](#匹配来源与规则类型) · [编辑器选项](#编辑器选项) · [DNS（OxiDNS）怎么选](#dnsoxidns-怎么选) · [列表与批量操作](#列表与批量操作) · [检查与发布](#检查与发布)

入口：**当前配置 → 策略规则**。规则从上到下匹配，先命中的通常决定结果。这里同时管理连接去向与 OxiDNS 的域名查询去向：**「策略」管连接走哪个出口，「DNS」管先向谁查询域名**，两者可以不同。

规则属于顶部当前配置空间。引用的规则库名单是共享的；改变一条引用的策略只影响本配置，进入「编辑来源」改名单内容则会影响所有使用者。

## 先加一条规则

1. 先确认当前配置空间，并已有可用 [策略组](proxy-groups.md)。
2. 点「添加规则」，匹配来源选「输入规则」。
3. 规则类型选 `DOMAIN-SUFFIX`，匹配值填 `example.com`，表示这个域名及子域名。
4. 「策略」选择想用的代理组，或 `DIRECT`。
5. 使用 OxiDNS 且希望查询与连接一起调整时，DNS 选择「跟随策略」；只想改变连接、不动 DNS 时选「默认上游」。
6. 新规则通常放顶部，保存后用「命中模拟」核对，再生成并发布到正确设备。

不要把需要优先匹配的规则放到兜底 `MATCH` 后面。`MATCH` 用于处理前面都未匹配的连接，通常放最后。

`MATCH` 后面的规则只对 Mihomo 有意义：规则命中的代理节点不支持 UDP 时，Mihomo 会跳过这条规则继续向下匹配，只有这类连接才会走到 `MATCH` 之后。列表把这些规则标为「仅 Mihomo」；生成 Surge、Loon 配置时它们写成注释，`FINAL` 始终在最后。想统一处理这类 UDP，用 `MATCH` 规则的「节点不支持 UDP 时」，不必手写规则。

## 匹配来源与规则类型

| 来源 | 怎样使用 |
| --- | --- |
| 输入规则 | 适合少量域名或 IP，可每行一个值，也可带类型前缀。无前缀的行按所选类型解释；看解析预览再保存。当前批量输入最多 200 条，超过约 20 条会建议改为规则集。 |
| 规则库 | 引用已经存在的共享名单。已引用的项目不会重复添加，停用来源须先在规则库启用。编辑已有引用可换一个来源，顺序、备注及 DNS 保留，仍须核对新名单内容。 |
| 新建规则集 | 一次建立共享名单并在当前配置引用它；名称、远程地址/粘贴内容、Domain/IP/Classical、Text/YAML/MRS 的含义见 [规则库](rule-library.md#添加规则集)。注意新名单可被其他配置继续引用。 |

| 规则类型 | 匹配什么；推荐用途 |
| --- | --- |
| DOMAIN | 完整域名精确匹配，适合一个主机。 |
| DOMAIN-SUFFIX | 域名及其子域名，适合整个站点；是常见起点。 |
| DOMAIN-KEYWORD | 域名含某段文字就匹配，范围可能很大；有明确需求再用。 |
| IP-CIDR／IP-CIDR6 | 目标 IPv4/IPv6 网段，仅用于连接分流。 |
| IP-SUFFIX | 目标 IP 后缀条件；熟悉目标核心规则语法时使用。 |
| DST-PORT／SRC-PORT | 目标／来源端口；可能影响多个完全不同的网站，不能替代域名规则。 |
| GEOIP／GEOSITE | 使用目标核心的地理 IP／站点分类数据；类别名和可用数据必须匹配核心配置。 |
| RULE-SET | 引用目标核心认识的规则集；普通用户优先通过「规则库」入口选已管理来源，减少写错名称。 |
| AND／OR／NOT | 组合条件。因表达式可含逗号，每次单独加一条；不会按普通多行批量输入拆开。 |
| NETWORK | 按传输协议 `tcp`／`udp` 匹配，常放在 AND 里与端口组合，例如 `((NETWORK,udp),(DST-PORT,123))`。Surge、Loon 生成时改写为 `PROTOCOL,TCP`／`PROTOCOL,UDP`。 |
| MATCH | 无需普通匹配值的最后兜底，通常指向默认出口。 |

不同目标软件支持的类型不完全一致，最终以生成和核心校验结果为准。端口规则用 `/` 或 `,` 写多个端口（如 `443/3478`）只有 Mihomo 支持，Surge、Loon 生成时写成注释，需要时拆成多条。导入的其他类型可能仍保留在原配置中，不代表本页面新增菜单提供所有核心语法。

## 编辑器选项

| 选项 | 怎么改；保存后结果 |
| --- | --- |
| 无前缀的行按／规则类型 | 给裸输入选解释方式；已带类型的行按自身类型处理。不能只改下拉框就把错误内容变成有效规则。 |
| 匹配值、解析预览 | 查看每行会变成哪条规则；无效行需要修正或删除。批次中有无效行时不能把其他行默认为已保存。 |
| 已有重复提示 | 已存在的直接规则会被识别并跳过；已有停用规则可按提示启用，不必重复创建。 |
| 改为新建规则集 | 把较多输入整理成一份共享名单；后续修改名单影响所有引用它的配置。 |
| 测试地址 | 新建远程规则集时检查来源 URL。成功只说明当时能取得响应，不等于所有规则都符合每个目标核心。 |
| no-resolve | 仅相关 IP/逻辑规则出现。开启后不为了匹配这条 IP 条件主动解析域名；关闭允许核心按规则需要解析。已有目标 IP 仍可匹配。需要避免额外 DNS 查询时开启，想用 IP 条件处理域名连接时核对影响。 |
| 策略 | `DIRECT` 直连、拒绝类策略阻止连接，或选择代理组。不会因组名写着“国内”就自动保证 DNS 直连。 |
| 节点不支持 UDP 时 | 仅 `MATCH` 规则出现。规则命中的代理节点不支持 UDP（例如没开 udp 的 ss 节点）时，QUIC、STUN 等 UDP 连接的去向。「客户端默认」不额外写入：Mihomo 与 Loon 直连，Surge 6 起拒绝。「直连」能通但绕过代理，网站可能看到真实 IP。「拒绝」时 Mihomo 在全部规则最后追加 `NETWORK,udp,REJECT`，Surge 写入 `udp-policy-not-supported-behaviour`，Loon 写入 `udp-fallback-mode`；浏览器的 QUIC 会改用 TCP 走代理。选拒绝前，把 NTP 对时等应直连的 UDP 放进前面的直连规则。Surge、Loon 基础配置的 `[General]` 已写对应项时以基础配置为准。列表里的 `MATCH` 会显示当前选择。 |
| DNS（OxiDNS） | 见下一节；仅控制 OxiDNS 域名分流。 |
| 更多选项 → 备注 | 给自己留说明，不影响匹配。 |
| 分组名 | 把相邻规则整理成可折叠显示的组，不是新增一个代理出口。 |
| 插入位置：顶部／底部 | 新增时决定优先级；具体规则通常放前面，兜底放后面。 |
| 启用／停用 | 开启参与生成；关闭保留这条设置但不参与正常匹配，后续规则可能接管。 |
| 保存／取消 | 保存当前配置草稿或放弃未保存修改；保存不是发布。 |
| 编辑来源／保存来源 | 修改共享规则库内容。即使随后取消外层规则编辑，已经保存的共享来源改动也不是自动撤销。 |

## DNS（OxiDNS）怎么选

只有可转换的域名规则参与 OxiDNS 标准 DNS 分流。**纯 IP 规则显示“不参与”；Classical 混合规则集只使用域名部分。** IP、端口、进程等连接条件不能直接当成域名查询条件。混合粘贴时，所选 DNS 只作用于域名行。

| DNS 选项 | 结果；推荐场景 |
| --- | --- |
| 跟随策略 | 按这里保存的连接策略推导直连或代理 DNS，改策略时一起更新；一般分流可用。无法判断时按界面推导处理，不能依赖组名猜测。Mihomo 面板临时换节点不会改变它。连接策略选拒绝时，DNS 按默认上游处理。 |
| 默认上游 | 不给这条规则另设 DNS；其他域名 DNS 规则仍可能命中，最终才使用 OxiDNS「未匹配时转发到」。适合只改连接去向。 |
| 直连 DNS | 固定使用 OxiDNS 的直连 DNS 列表；之后连接改成代理也不会自动变。适合明确需要直连解析的域名。 |
| 代理 DNS | 固定使用代理 DNS 列表；“代理”是这组上游的名字，不代表系统自动给该上游加了网络代理。 |
| 指定上游 | 只使用明确选中的一个上游，适合公司内网域名。保存固定当前地址，之后改上游列表不会自动改此规则；独立转发/缓存，不与其他上游竞速，失败返回 SERVFAIL。 |
| 拒绝 | 返回 REFUSED，立即拒绝查询；一些客户端会改问其他 DNS，不能当成所有客户端都无法绕过的网络封锁。 |
| 不存在 | 返回 NXDOMAIN，告诉客户端域名不存在；适合拦截域名。 |
| 空应答 | 返回成功但没有记录，针对所有查询类型，包括 IPv4。**不是只屏蔽 IPv6**；只限制 AAAA 应在核心设置处理查询类型。 |
| 黑洞 | A 返回 `0.0.0.0`、AAAA 返回 `::`（优先 IPv4 开启时为空），其他类型空应答；客户端可缓存 300 秒。适合某些对“不存在”反复重试的应用。 |

自定义 Hosts、AdGuard 过滤以及设备「全部直连」等更早的处理可能优先于这些规则。高级自定义执行链若不支持可视编辑，页面会显示锁定或原因；不要把只读状态理解为“已经应用了你想要的 DNS”。

「跟随」出现偏离提示时，说明当前 DNS 与保存的策略推导不一致；可用「按策略更新 DNS」重新对齐，或明确选择固定 DNS。固定选择不会被以后改连接策略悄悄改掉。

## 列表与批量操作

| 操作 | 用途与边界 |
| --- | --- |
| 点策略单元格 | 快速修改这一条连接去向。分组头上的策略操作会改整组，先看清范围。 |
| 点 DNS 单元格／分组 DNS | 修改一条或批量设置整组的 DNS；不支持的类型不会因此变成域名规则。 |
| 更多 → 统一为跟随策略 | 把符合条件的 DNS 选择统一改为跟随，会影响原来固定的选择；有内网专用 DNS 时先核对提示范围。 |
| 更多 → 调整顺序 | 拖动规则或分组并保存；会改变匹配优先级，不只是美观排序。取消还原本次排序。 |
| 重命名分组 | 只改整理标签，留空显示数量；不改变规则目标。 |
| 全部展开／收起分组、卡片／列表 | 只改显示，不停用规则。 |
| 规则集名称旁查看来源 | 进入规则库核对实际内容；排序时跳转可能暂不可用。 |
| 启用／停用 | 即时保存草稿状态；关闭后下一条可匹配规则可能接手。 |
| 删除 | 删除当前配置里的直接规则或规则集引用；删除引用不等于把共享规则库来源也删掉。 |
| 查找重复 | 检查直接规则和可读取规则集中的完全重复项，展示位置和检查范围。读取失败的来源不算已检查；“没有重复”不等于没有重叠或遮挡。 |
| 重复结果里的删除 | 可删除对应直接规则；规则集内部条目应回来源修改，且会影响共享使用者。 |

## 检查与发布

「命中模拟」输入域名或 IP，按当前顺序检查规则及能读取的规则集，展示匹配位置。它是配置层检查，不会替你验证目标设备路由、DNS、代理连通性；当前无法模拟的条件或来源错误应阅读提示，不能把结果当成端到端联网保证。

保存规则的 DNS 修改会写入同一配置空间的 OxiDNS 草稿，因此重新打开 [OxiDNS 设置](core-settings.md#oxidns-编辑入口) 能看到它。需要让连接与解析都改变时，分别检查 Mihomo 和 OxiDNS 的生成结果，并向相应设备发布；只发布其中一个，另一侧可能仍运行旧设置。
