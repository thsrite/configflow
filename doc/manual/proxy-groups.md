# 策略组：决定一条连接使用哪个出口

本页目录：[先建一个常用组](#先建一个常用组) · [类型怎么选](#类型怎么选) · [名称和节点来源](#名称和节点来源) · [健康检查和负载策略](#健康检查和负载策略) · [代理链](#代理链) · [页面操作与生效](#页面操作与生效)

入口：**当前配置 → 策略组**。这里的“当前”指页面顶部选中的配置空间。组里的节点可以来自全站共用订阅、节点库或聚合；创建策略组只保存“这个配置怎样选出口”，不会改掉原节点。

## 先建一个常用组

1. 顶部切到目标配置空间，点「添加策略组」。
2. 名称填“代理选择”，类型用「手动选择」。
3. 勾选「订阅」，在「订阅筛选」选自己的来源；初次不要加正则。
4. 保存，检查右侧「命中节点」不为空。
5. 在 [策略规则](rules.md) 中把需要代理的域名指向“代理选择”，然后生成并发布。运行后在目标设备的 Mihomo 面板切换实际节点。

## 类型怎么选

| 类型 | 怎么工作 | 适合谁；需要留意 |
| --- | --- | --- |
| 手动选择（Select） | 由你在客户端或核心面板选择成员 | 最容易理解的起点。保存这个组不等于已经在运行设备上切换了节点。 |
| 自动测速（URL-Test） | 核心按测试结果选择延迟较低的可用成员 | 希望少手动切换时使用；测试 URL 必须适合这些节点。通过容差减少频繁切换。 |
| 故障转移（Fallback） | 按成员顺序使用可用节点，前面的优先 | 有明确主用、备用时使用；不是“总选最快”。顺序有实际意义。 |
| 负载均衡（Load-Balance） | 按负载策略把不同连接分配给成员 | 多个出口都可用且接受出口可能不同的场景。不会把一条下载连接合并成多倍带宽。 |
| 代理链（仅 Mihomo） | 连接先经过前置，再由落地访问目标 | 明确需要两跳时才使用。增加依赖与延迟；不能按普通组直接导出 Surge/Loon。 |
| 跟随策略 | 复制被跟随组的类型、来源、健康检查等配置，只保留自己的名称 | 想为相同设置建立另一个规则目标时使用。它是配置跟随，不保证实时同步两个独立组在运行面板中的手动选择。 |

## 名称和节点来源

| 选项 | 推荐怎么选；勾选／取消的结果 |
| --- | --- |
| 名称 | 用用途命名，例如“代理选择”“视频”“内网”。规则会引用这个名称，改名后应检查依赖关系。 |
| 节点来源：订阅 | 勾选后出现「订阅筛选」，加入所选订阅的可用节点；取消则本组不再使用这类来源，不删除订阅。 |
| 订阅筛选 | 可选多个启用来源。来源自身已过滤掉的节点不会在这里重新出现。 |
| 订阅的保留正则 | 留空保留候选订阅节点；有值时只保留名称匹配者。例子见下方。 |
| 订阅的排除正则 | 在保留筛选之后再排除。留空不排除，适合去掉说明行或不想使用的节点。 |
| 手动节点／包含节点 | 勾选来源后选择节点库中的独立节点；取消某项仅解除本组引用。 |
| 订阅聚合／引用聚合 | 引用 [聚合](subscription-aggregation.md) 已筛过的结果；聚合变化会影响之后生成的本组。 |
| 聚合的保留／排除正则 | 在聚合自身过滤之后再筛一次，先保留、再排除；留空则不增加这一层限制。 |
| 引用策略 | 把已有策略组作为可选成员。适合“总开关组包含自动组和手动组”；不能循环引用自身或形成环。 |
| 跟随策略／跟随目标 | 与其他来源互斥；选定后沿用目标组的配置，独立来源和测试参数不再单独编辑。 |
| 顺序调整 | 拖动已选节点、聚合与策略的顺序。手动选择默认成员、Fallback 主备顺序等会受影响。 |
| 预览 | 检查筛选后命中了哪些节点，不执行设备端测速，也不保存输入。 |
| 策略组启用中／已停用 | 开启进入正常生成；关闭保留配置但停用本组，需检查其他组或规则是否依赖它。 |

正则例子：保留香港或日本可填 `香港|HK|日本`；排除说明行可填 `到期|剩余|广告`。保留正则可用反引号 `` ` `` 分成几段，Mihomo 按段的先后排列节点，同一节点只出现一次。例如 `` 香港`日本 `` 让香港节点都排在日本节点前面，适合固定 Fallback 主备顺序；预览按同样的顺序显示。排除正则里的反引号只当普通字符。先用「预览」确认结果，再保存。来源、聚合、本组连续多层过滤，任何一层都可能把节点清空。

## 健康检查和负载策略

URL-Test、Fallback、Load-Balance 提供「健康检查」。新建组默认 URL 为 `https://www.gstatic.com/generate_204`，间隔 **60 秒**、超时 **5 秒**、预期状态 `204`、懒惰检测为“否”；新建 URL-Test 容差 **50 毫秒**。这与订阅/聚合来源的 300 秒、懒惰检测默认不同。旧配置中的「未设置」保留旧有行为，不要仅为界面齐全而强行补值。

| 选项 | 推荐与结果 |
| --- | --- |
| 测试 URL | 使用这些节点应该能成功访问的 HTTP(S) 地址。公共测试站不适合所有内网节点；改变地址后也核对预期状态。 |
| 测试间隔（秒） | 默认 60 秒；更短更频繁、开销更大，范围 1–86400。 |
| 超时（秒） | 默认 5 秒；适当放宽可避免慢网络误判，过长会延迟失败判断。 |
| 预期 HTTP 状态 | `204` 或 `200-299/304` 等；必须对应测试站实际响应。 |
| 懒惰检测 | “是”按使用情况减少无用探测；“否”持续按间隔检测。希望备用节点及时跟上状态时可保留组的默认“否”。 |
| 容差（毫秒） | 仅 URL-Test；减少为很小的延迟优势来回切换。一般从新建默认 50 开始，不必追求每次都低 1 毫秒。 |
| 负载策略：轮询 | 成员轮流承担连接，适合不要求固定出口的场景。 |
| 一致性哈希 | 尽量把相同特征的目标分配到相同出口，适合减少无规律变化。 |
| 会话保持 | 尽量让同一会话保持出口；仍不能保证所有网站永远看到同一个公网 IP。 |
| 批量测速地址 | 只修改当前配置中选定的 URL-Test/Fallback/Load-Balance 组的测试 URL；跟随组沿用来源组。打开后会预选可操作组，先核对范围再点「应用到 N 个策略组」。 |

节点库的测速来自 ConfigFlow 主机；组健康检测运行在目标核心上，两者网络路径不同。右侧命中数量与“默认选中”也不是实时测速成绩。

## 代理链

| 字段 | 怎么选 |
| --- | --- |
| 搜索节点或策略组 | 过滤候选名字，避免在大量节点中选错。 |
| 前置节点或策略组 | 第一个经过的出口。选择策略组时使用该组当前选中的节点；必须是可用且启用的来源。 |
| 落地节点或策略组 | 最后访问目标的出口。落地选策略组时，系统为这条链单独创建一组，原组仍可单独使用。 |
| 启用 | 启用前必须保证两端可用。停用链时可以暂存已停用的落地，但不能因此当成已部署可用。 |

两端可使用手动节点、策略组或其他代理链，但不能循环。订阅/聚合中的节点随来源更新变化；链的预览正确不等于两跳都能连通。生成或发布因缺失来源报错时，应修正引用，不能用同名节点假装原引用仍在。

## 页面操作与生效

桌面左侧选择组、右侧看来源与筛选；小屏通过「选择策略组」切换。右侧直接改来源或正则后会出现「还原／保存」：还原丢弃这次草稿，保存才写入当前配置。添加/编辑弹窗中的「取消」同样不保存。

「调整顺序」改变组在配置中的顺序；排序窗口可以拖动、上下移、置顶或置底，保存后提交。它和组内成员顺序是两件事。

删除组前先改好引用它的规则、其他组和代理链；出现依赖提示时按提示处理。停用、改名、批量改 URL 或保存后，都需重新生成并发布才会改变设备配置；在这里操作不会直接替所有设备切换网络出口。
