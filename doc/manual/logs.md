# 日志

[文档首页](../README.md)

入口：**系统 → 日志**。日志是面板做过哪些事、在哪里出错的文字记录。这里显示 ConfigFlow 服务端日志；Mihomo、OxiDNS 或 Agent 自己的运行日志，要到对应面板或 Agent 卡片查看。

## 推荐的排查步骤

1. 记住出问题的时间和操作，例如“17:10 更新订阅失败”。
2. 打开日志，先保留 `WARN`、`ERROR`，输入订阅名、设备名或错误关键词。
3. 找到同一时间附近的记录，向前后看几行，不要只截取最后一句。
4. 若日志不断滚动，点 **暂停**。复制或截图前遮住订阅地址、密码、令牌和私人地址。
5. 回到原页面处理原因，再重试一次，查看新的结果。

## 每个按钮有什么作用

| 选项 / 按钮 | 作用 | 推荐怎么用 |
| --- | --- | --- |
| DEBUG | 较详细的调试记录 | 默认服务通常不产生这类记录；点开筛选不会自动开启调试模式 |
| INFO | 正常操作记录 | 想知道之前做了什么时保留 |
| WARN | 警告，需要留意但未必失败 | 与错误一起看，不要看到警告就认定整个服务停止 |
| ERROR | 错误和严重错误 | 排查失败时优先保留，再结合前面的 INFO 判断原因 |
| 关键词搜索 | 按文字查找日志，并在结果里标出命中的文字 | 先用名字或错误短语，不必粘贴整行 |
| 显示行数 | 100、200、500、1000、全部 | 默认 200；更早的问题选更多。“全部”当前最多请求 10000 行，不是无限历史 |
| 暂停 / 继续 | 暂停或恢复网页的自动读取 | 只影响显示，**不会暂停实际服务，也不会停止写日志** |
| 刷新 | 立即重新读取 | 不会重跑刚才失败的任务 |
| 到底部 | 跳到当前最新记录 | 想继续看后续结果时使用 |
| 清空 | 确认后清空当前日志文件 | 先保存排错证据；它不会修复错误，也不是清除配置 |

每条记录之间有细分隔线，堆栈等续行跟在所属记录下面，不另画线。正文原文不改动，引号里的名称（如订阅名、节点名）为青色，`error:` 之后的错误原因为红色，与 Mihomo 面板的日志显示一致。

页面默认每 3 秒读取一次新记录。停在底部时会跟随新内容；向上翻看时不会强迫你跳回底部。取消勾选某一级别只是隐藏这些行，不会删除文件。
