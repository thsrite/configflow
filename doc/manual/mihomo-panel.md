## 设备、模式和顶部按钮

1. 从 Agent 卡片点 **Mihomo 面板**，或从侧栏进入。
2. 在标题旁核对所选设备，检查 IP、Agent 在线状态、核心状态和版本。
3. 若提示无法读取核心，先用 **重试**或 **查看日志**检查；需要升级 Agent 时按页面入口处理。
4. 默认打开 **概览**标签。其他标签是 **统计、策略、连接、规则、日志**。

设备选择优先使用当前链接指定的设备，其次记住上次选择；没有可用选择时优先选在线设备。切换设备只是更换管理目标，不会把一台配置复制到另一台。

| 控件 | 默认/推荐 | 影响与回退 |
| --- | --- | --- |
| 规则 / 全局 / 直连 | 显示核心实际模式；日常分流通常使用“规则” | 点击立即修改运行模式。规则按已加载规则分流；全局使用全局策略；直连将流量按直连模式处理。选回原模式可恢复模式选择，不会撤销已经建立或断开的连接。 |
| 刷新 | 按需点击 | 重读核心状态、模式和当前标签数据，不发布草稿、不重新下载所有订阅。 |
| 内核 | 有维护需要时使用 | 打开维护菜单，详见[内核操作](#core)。 |
| 设置 | 修改长期配置前使用 | 打开当前设备实际绑定空间的“Mihomo 基础配置”，与侧栏当前空间可能不同。 |

运行模式和手动节点选择不是 ConfigFlow 草稿编辑；不要依赖这次临时操作替代配置管理。后续重载、重启或重新发布时，结果还受配置默认值和核心自身保存选择的设置影响。

## 概览：流量、拓扑、延迟和规则命中

概览把这台设备的运行情况放在一页，只读，不改任何设置。只在概览标签可见时读取数据，切到其他标签或隐藏浏览器页面后暂停。

| 区块 | 内容 | 说明 |
| --- | --- | --- |
| 顶部六格 | 连接数、累计上传/下载、内存使用、上传/下载速度 | 累计量是内核启动以来的总量，内核重启后清零。速度和内存的趋势图覆盖本页最近约 2 分钟。 |
| 连接拓扑 | 来源设备 → 命中规则 → 策略组 → 出口节点 | 与“数据统计”页的实时流量相同，固定显示当前设备。按最近一次采样的速率绘制，每列最多 6 项；点节点到“连接”查看明细。需要 Agent 1.8.26-go 或更新版本。 |
| 延迟 | 百度、Google、Cloudflare、GitHub、YouTube | 右上角选测试方式，选择记在当前浏览器。**经 Mihomo**（默认）：由 Mihomo 发起测试，反映这台设备的出网质量，与你所在的网络无关；百度走直连，其余站点走所选策略组当前的出口，默认是配置里的第一个策略组。**经浏览器**：与 zashboard 相同，在你的浏览器里加载各站点的小图标计时（包含建立连接的时间），反映的是你这台设备访问这些站点的体验，走不走代理取决于这台设备的网络设置。两种方式的结果分开保存。打开时测一次，之后每分钟重测，柱条是最近 5 次结果，柱子越高延迟越大。“超时”表示这次没有拿到有效延迟。 |
| 规则命中 | 命中最多的 10 条规则、次数、目标策略和最近命中时间 | 次数由内核统计，从内核启动或重载配置起累计，重启后清零。需要 Mihomo v1.19.19 或更新版本，旧内核显示“内核没有提供命中次数”。完整规则顺序在“规则”标签查看。 |

## 统计：按设备、目标和链路看流量

“统计”标签只放连接统计：按设备、目标、链路、出站节点或策略组汇总流量，列出每组走的链路，分直连和代理。只在这个标签可见时读取数据。

默认是“实时”：汇总当前活动连接，流量是每条连接建立以来的累计字节，速度来自最近两次采样之差，连接关闭后不再计入。开启“后台记录”后可切到 24 小时、7 天、30 天，见下方说明。目标按主域名归并（如 `a.b.example.com` 计入 `example.com`）；设备名称来自“客户端设备”的备注。聚合方式和范围记在当前浏览器。

**链路**：一条连接从规则命中的策略组出发，经过各层策略组，到最终的出口节点，例如“人工智能 → 美国自建 → IEPL 专线”。表格按分组列出：每台设备（或目标、策略组）一行合计，下面直接列出它走的链路及各自的流量，不用点开。每组默认显示流量最大的 3 条，其余折成“其余 N 条”，点一下显示全部；点行首箭头收起这一组，表头的“收起明细 / 展开明细”一次收起或展开全部。按链路或出站节点汇总时反过来，每行是一条链路（或一个节点），下面列出使用它的设备。

**直连还是代理**：按链路最后一层的出口节点判断。出口是 `DIRECT` 或配置里 `type: direct` 的节点算直连，`REJECT` 类算拦截，其余算代理，节点类型以 Mihomo 当前加载的配置为准。汇总里的“直连 / 代理”两格写明各自占比；分组行显示直连占比，链路行标出“直连 / 代理 / 拦截”。“未归属”不分设备，也分不出直连还是代理。手机等窄屏只显示名称、直连占比（或类型）和总流量，链路最多折成两行。

### 后台记录流量

“统计”标签里的 **后台记录** 默认关闭，按设备分别开启。开启后，所选设备的 Agent 在后台持续采样 Mihomo 的连接，不打开页面也照常统计，可以查看最近 24 小时到 30 天里每台设备、每个目标、出站节点和策略组用了多少流量，包括已经关闭的连接。

- **需要 Agent 1.8.51-go 或更新版本**，旧版本开关不可用并提示更新。只支持 Mihomo Agent。1.8.51-go 只记录入口策略组和出口节点两层，中间各层要更新到 **1.8.52-go** 才会记录，记录栏会提示；更新前已记录的数据仍按两层显示。
- **会记录什么**：按小时累计每台设备经过 Mihomo 的上传、下载和新建连接数，按设备分别记录走的完整链路和访问的主域名（或 IP）。不记录网址路径和内容。这相当于家里各设备的上网记录，开启前确认使用这台网关的人都知道。
- **多久更新**：Agent 每 5 分钟上报一次，刚开启时等几分钟才有数据；服务端先放在内存里，按[系统设置 → 定时任务](system-settings.md)的“监控历史保存”间隔（默认 30 分钟）写入数据目录的 `metrics/traffic_history.sqlite3`，服务停止时也会保存。意外断电最多丢失一个间隔的记录。
- **未归属**：在两次采样之间开始又结束的短连接（Agent 约每 1 秒采样一次，连接超过 2000 条时放慢到 2 秒、超过 5000 条时 5 秒），只能从内核总量算出合计，记为“未归属”一行，不分设备。
- **数据量**：近 7 天按小时保存，更早的按天合并；目标近 2 天按小时，更早的按天保存且每台设备每天只留流量最大的 100 个，其余并入“其他目标”。范围边界按整天计算。10 台左右的设备保留 90 天，数据库一般在几十 MB 以内。
- **保留时长**：可选 30、90（默认）、180、365 天，所有设备共用；缩短后，超出的记录在下次保存时删除，需要确认。
- **清空记录**：删除这台设备已记录的全部流量，开关保持开启，之后继续记录；不能撤销。
- **关闭**：会询问“停止并保留”或“停止并删除”。保留的数据在重新开启后接着显示，按保留时长逐步过期。删除 Agent 时，它的记录一并删除。

记录不在配置导出和 WebDAV 备份里。

## 策略：选择、固定和测速

策略组决定一类流量走哪个节点。卡片显示组名、组类型、当前选择和测速结果；展开后可看组内成员。

### 选择节点

| 组类型 | 能否手动选择 | 选择后的行为 |
| --- | --- | --- |
| 手动选择 | 可以 | 后续按所选成员出站。需要恢复时选回原成员。 |
| 自动测速 | 可以 | 手动点选会固定该成员，不再按原来的自动选择结果切换。点组上的“取消固定”交回内核。 |
| 故障转移 | 可以 | 同样会固定；需要继续自动故障转移时点“取消固定”。 |
| 负载均衡 | 不能直接手动选成员 | 出口由内核分配，可查看和测速；需要改成员/算法时编辑配置并发布。 |
| 链式代理 | 不能直接手动选成员 | 按配置组成链路，不能当作普通单选组操作。 |

点击节点会立即调用核心，不需要保存按钮。默认开启“切换节点时自动断开连接”，所以会尝试断开经过该组的旧连接，让客户端重连到新选择；其他使用相同组的设备也可能受影响。正在下载或开会时先按[代理设置](#display)决定是否关闭这个开关。

### 搜索、展开和测速按钮

| 控件 | 用法和范围 |
| --- | --- |
| 搜索策略组或节点 | 默认空。输入后只过滤当前展示；命中组名时展示该组成员，命中成员名时展示相应成员。清空即可恢复。 |
| 全部展开 / 全部收起 | 批量展开或收起组卡片，不切换出口。 |
| 组上的测速图标 | 测量该组成员的延迟。自动类型组的最终选择仍受内核逻辑/固定状态影响。 |
| 单节点测速 | 测量该节点到测试地址的延迟，显示毫秒；不是下载带宽测试。 |
| 当前出口测速 | 成员本身是下级组时，先读取核心里它当前的出口再测，不递归测试下级所有成员。失败时提示写明实际测的出口；自动测速组刚重载、还没测过速时可能先用列表第一个成员。 |
| 全部分组测速 | 逐组测速，**包含隐藏代理组**，显示已完成组数。可能产生较多网络请求，日常先测有问题的一组即可。 |
| 停止后续测速 | 不再开始队列中后面的组，当前正在执行的一组允许完成。 |
| 取消固定 | 仅固定的自动测速/故障转移组需要使用，立即恢复内核自动选择。 |

“—”表示还没有可用测速结果；“超时”表示该次测试未得到有效延迟。测试地址来自组配置，访问测试地址慢不一定代表所有网站都慢。多个来源存在同名节点时，页面可能要求使用所属组的“分组测速”，避免测错来源。

### 代理集合

页面下方的“代理集合”显示核心已加载的来源、节点数、流量/到期信息和更新时间。

- **健康检查**：让核心检查该集合里的节点可用性，完成后刷新结果。不会修改 ConfigFlow 的订阅来源地址。
- **更新**：只为可在线更新的 HTTP 集合显示，要求核心重新读取该集合的当前内容。内容变化后可能影响节点列表和自动选择。
- 不显示流量或到期信息时，可能是来源没有提供，不能自动认为“流量无限”。

若上游订阅内容有误，更新可能把错误内容也取回来。修正订阅来源/配置后重新更新或发布；这个按钮没有“恢复上一次订阅内容”的独立撤销功能。

## 代理设置的每个开关

策略工具栏的齿轮打开 **代理设置**。这些偏好保存在当前浏览器，修改立即应用，不需要发布；换浏览器不保证沿用。除了“切换时断开连接”会影响后续切换操作，其余都是显示方式。

| 设置 | 初始默认 | 开启/关闭或选项效果 | 建议 |
| --- | --- | --- | --- |
| 排序方式 | 按配置排序 | 可改按延迟、按名称排序；只调整卡片显示顺序，不改策略优先级 | 先按配置；对比速度时改延迟排序。 |
| 节点根据提供商分组 | 关闭 | 开启后按来源把成员分段；关闭后一起排列 | 多订阅、同名节点较多时开启。 |
| 隐藏不可用节点 | 关闭 | 开启后隐藏已知超时/不可用成员，但当前所选仍保留；关闭能看到它们继续排查 | 故障排查时保持关闭。 |
| 管理隐藏代理组 | 关闭 | 开启后能看到配置标记为隐藏的组；不会改写配置的隐藏标记 | 需要管理隐藏组时开启，结束后可关。 |
| 切换节点时自动断开连接 | **开启** | 开启时切换后尝试断开经过该组的旧连接；关闭时保留旧连接，新连接使用新选择 | 想立即换出口时开启；需要保住长连接时先关闭。 |
| 显示最终出口节点 | 关闭 | 开启时沿下级组的当前选择展示最终节点，便于看清多层策略 | 嵌套组多时开启；只是显示，不强制出口。 |
| 禁用代理页文字选中 | 开启 | 开启避免点卡片时选中文字；关闭便于复制组名/节点名 | 要复制名称时临时关闭。 |
| 节点卡片最小宽度 | 145 | 可调 100–320；数字越大卡片越宽、一行越少 | 名称长可适当增大；“重置”恢复宽度 145，不重置全部偏好。 |

若浏览器已经存过偏好，看到的是上次保存的值，不一定是表中的初始默认。改变这些偏好后，无需到 Agent 页推送。

## 连接：筛选、分组和断开

连接数、累计流量、内存和速度在[概览](#overview)查看，本标签只放连接列表。

### 查看范围和刷新

| 控件 | 默认 | 效果 |
| --- | --- | --- |
| 活跃 / 已关闭 / 全部 | 活跃 | 已关闭是打开此页后在采样中观察到消失的连接，最多保留最近 500 条。它不是核心的完整历史；切换设备或刷新页面后会清空。 |
| 实时 | 开启 | 当前连接页可见时约每 2 秒读取；关闭后只暂停页面采样，网络连接仍继续。重新开启即可恢复。 |
| 清空记录 | 仅“已关闭”标签出现 | 立即清空本页保存的关闭记录，不断开当前连接、不删除服务端日志；没有撤销。 |
| 上一页 / 下一页 | 第一页 | 每页最多 100 条；开启分组时按组分页，展开的成员另行显示。 |

“Inner”表示核心自己产生、没有普通来源 IP 的连接，例如 DNS 上游或测速，并不是一台名叫 Inner 的终端。读取失败时页面会保留上次连接快照，先恢复读取再判断当前连接数。

### 搜索与筛选

搜索框默认空，支持忽略大小写的正则；正则格式无效时按普通文本搜索。可以搜主机、IP、设备备注、规则、进程等，未显示的列也参与匹配。

点 **筛选**可设置：

| 条件 | 怎么用 |
| --- | --- |
| 来源 | 按客户端 IP/设备备注选择，可多选。 |
| 协议 | 按连接协议选择，可多选。 |
| 规则 | 选命中的规则，可多选。 |
| 链路 | 选经过的策略组或节点，可多选。 |
| 隐藏匹配的连接 | 默认空；匹配的内容从结果中排除，也支持正则，适合隐藏测速等背景请求。 |

同一项多选是“符合任意一个”，不同项之间需要同时符合。比如选两台来源且选 TCP，结果是这两台的 TCP 连接。筛选修改立即影响表格；**完成**只关闭筛选框，**清除/清除筛选**同时清空搜索与筛选条件。

筛选只影响显示和“断开筛选结果”的目标，不会自动建立分流规则，也不会阻止以后出现类似连接。

### 排序、分组和显示列

- 默认按 **最新活动**降序，默认不分组。可从排序下拉选择主机、来源、类型、规则、链路、速度、流量、时长、开始时间、进程或总速度/总流量；方向按钮切升降序，表头也可排序。
- 分组可按主机、来源、类型、规则、链路。点组名展开；组的速度、流量是合计，时长显示最长成员。**全部收起/取消分组**只改表格。
- 大组初次展示前 20 个成员，用 **继续显示本组**逐批展开，不代表剩余连接被隐藏筛选或断开。
- **设置显示列**默认勾选主机、来源、类型、规则、链路、下载速度、上传速度、下载量、上传量、时长；开始时间和进程默认不勾选。
- 主机列始终保留。勾选某列后优先展示，桌面宽度不够时仍可能收起其他列；完整字段在连接详情可读。**恢复默认**只恢复显示列。
- 排序、分组、显示列记在当前浏览器；搜索和临时过滤条件不会跨设备沿用。

### 断开连接

每条活跃连接右侧的 **断开**图标立即关闭该连接。客户端可能自动重连，也可能导致下载、登录或通话失败；没有恢复原连接的撤销按钮。

批量按钮有两种：

- **全部断开**：没有筛选时，确认后请求核心关闭全部活动连接。
- **断开筛选结果**：有搜索/筛选时，确认后关闭当前匹配的活动连接，**包括其他页**。确认时会固定目标，不会因为后续轮询多出连接就悄悄扩大范围。

分组或只翻到某一页不会自动缩小批量操作范围。执行前先看确认框的范围和数量；不确定时取消，先缩小筛选，再断开单条验证。

<a id="detail"></a>
## 连接详情、备注和添加规则

点连接行或主机名打开“连接详情”，默认进入 **概览**。

| 标签 | 内容与操作 |
| --- | --- |
| 概览 | 连接时间、规则、入站、源地址、目标、嗅探域名、解析地址、进程、流量与代理链。字段缺失不代表页面能补回未上报的数据。 |
| 原始数据 | 展示核心返回的这条连接内容，仅查看。排错或分享时注意里面的域名、IP、进程等信息。 |
| 代理 | 从这条连接建立时的代理链入口查看当前策略；可点上方路径、查看下级、刷新策略。查看未选中的下级组不切换出口。 |

在“代理”标签点 **选择**会立即更改整个策略组，影响所有使用它的连接，不是只为当前这条连接换出口。自动测速/故障转移组手动选后固定；**恢复自动**交回内核。是否断开旧连接沿用[代理设置](#display)中的开关。下方“此连接建立时”保留原链路，不能把它误认为当前组的实时选择。

### 编辑来源设备备注

连接行的“更多”菜单 → **编辑来源设备备注**。填写如“客厅电视”，点 **保存备注**后立即保存到同一配置空间共用的备注表，不需要发布，也不改变 DHCP 主机名或分流。最多 80 个字符；留空保存可清除。需要管理多台时到“客户端设备”页。

### 加入代理规则集 / 加入直连规则集

这两个菜单把连接里的域名或真实目标 IP 写入**共享规则集**，不是仅为本连接做一次临时切换。

1. 核对弹窗显示的配置空间和规则集。域名使用该空间在“域名发现”设置的默认代理/直连规则集。
2. 选择连接域名/目标 IP。没有可用域名或真实 IP 时菜单不可用；不会将不合适的临时地址硬写入规则。
3. 域名默认 **仅此域名**；需要包含子域名才改 **此域名及其子域名**。
4. IP 默认 **仅此 IP**；改 **所在网段**会包含更多目标，IPv4 前缀初始为 `/24`、IPv6 为 `/64`。核对预览后再保存。不要为了一个网站无意扩大到整个网段。
5. IP 规则可选符合代理/直连策略的内容型 IP 或混合规则集；默认规则集不能使用时，需要明确选择一个可用目标。
6. 点 **确认添加**，检查新增、已覆盖或警告。规则集尚未启用时，还要在配置中启用并发布。

规则写入会影响其他引用同一规则集的配置。设备按现有规则同步机制生效，已经建立的连接不会因此被主动断开。要马上验证，先确认同步/发布成功，再新建连接；确实需要时手动断开旧连接。

添加错了，到规则仓库删除或修正该规则，再同步/发布。**取消**只能撤销尚未确认的添加，保存成功后的 **完成**不会撤销规则。

<a id="rules"></a>
## 规则：查看运行顺序和更新集合

这里展示核心**当前加载**的规则，编号反映运行顺序。编辑页面里尚未发布的规则不一定会在此出现。

| 控件 | 用途与范围 |
| --- | --- |
| 搜索规则类型、内容或策略 | 默认空，普通文本匹配，不区分大小写；清空恢复全部。显示“匹配条数 / 总条数”。 |
| 显示更多 | 首次显示前 200 条，每次再展示 200 条；只增加可见行数。 |
| 规则集合 → 更新 | 对该 HTTP 规则集合立即重新读取规则内容；本地文件类集合没有此在线更新按钮。 |
| 全部更新 | 依次更新全部 HTTP 规则集合，结果报告成功与失败数量；不修改草稿中的规则顺序或策略。 |

要新增规则、改顺序或改策略，请到配置编辑页面保存并发布。想刷新已有集合内容才用这里的“更新”；某个源失效时修正来源后再更新，批量更新失败不保证所有集合仍是原版本。

<a id="logs"></a>
## 日志：刷新和跟随

日志页读取 Mihomo **核心日志**，默认选第一个可读来源、自动每 3 秒刷新、开启 **跟随日志**，最多显示最近 500 行。它与 Agent 自己的日志不同。

| 控件 | 开启/关闭或点击的效果 |
| --- | --- |
| 日志来源 | 多来源时切换文件或系统日志，显示具体路径/服务名；切换会重新读取。 |
| 搜索日志 | 默认空，按普通文本忽略大小写过滤当前读取的行，不会搜索整个历史日志文件。 |
| 暂停刷新 / 恢复刷新 | 暂停/恢复页面轮询，核心仍继续写日志；页面隐藏或不在日志标签时也暂停读取。 |
| 刷新日志 | 立即重新确认来源并读取，即使自动刷新暂停也可以手动读取。 |
| 跟随日志 | 默认开启，读到新内容时滚到末尾；关闭后方便读上面的行，不停止采样。 |
| 重新读取来源 | 来源不可用时重新探测可读日志。 |

旧版 Agent 无法可靠区分核心/Agent 日志时，会提示升级，不会拿 Agent 日志冒充核心日志。读取失败会保留上次结果，核对更新时间。此页没有清空服务端日志按钮；日志维护见 [Agent 日志](agents.md#logs)。

<a id="core"></a>
## 内核菜单：重载、清缓存、更新和重启

这些操作直接发给所选设备。正在执行时暂时不能同时发起另一项内核操作；它们不负责发布 ConfigFlow 草稿。

| 菜单项 | 点击后何时生效 | 验证和回退 |
| --- | --- | --- |
| 重载配置 | 确认后从**核心当前使用的配置文件**重新加载。界面提示代理组选择会回到配置默认值，部分连接可能中断 | 看成功提示、刷新策略并访问实际站点。想加载新草稿必须先发布；选错节点可重新选择，文件错误应修正/回滚配置后再加载。 |
| 清空 FakeIP 缓存 | 点击后立即清理核心的临时地址映射缓存 | 适合排查旧映射问题；不能撤销清空，后续查询重建映射。不是关闭 FakeIP。 |
| 清空 DNS 缓存 | 点击后立即清理核心 DNS 缓存 | 后续查询重新解析，可能暂时变慢；不会清理其他 OxiDNS、路由器或客户端的缓存。 |
| 更新内核 | 确认后让 Mihomo 从官方发布页下载、替换自身并重启，网络短暂中断 | 页面只显示提交/等待上线阶段，没有逐文件下载进度。核对重新上线后的核心版本；失败时到 Agent 页看日志，必要时按原安装方式恢复已知可用核心版本。它不更新 Agent。 |
| 重启内核 | 确认后通过 Agent 重启 Mihomo 服务，所有连接会断开 | 等核心重新上线后刷新并从客户端验证。超时提示不等于一定重启失败，先查日志再决定是否重试。 |

对维护操作，先确认有其他方式能进入设备。已经断开的会话不能“撤销重启”恢复，只能由客户端重新连接。

<a id="settings"></a>
## 设置、保存草稿与发布

顶部 **设置**打开“Mihomo 基础配置”，可以编辑端口、DNS、TUN 等基础 YAML。生成时会合并这个配置空间的节点、策略组和规则；基础 YAML 并不是整台设备在线文件的反向导出。

**IPv6 模式**三选一：**关闭**（顶层 `ipv6: false`）、**Mihomo 用 IPv6，客户端走 IPv4**（完整名称「Mihomo 用 IPv6，客户端走 IPv4 分流」：`ipv6: true`、`dns.ipv6: false`，客户端保持 IPv4）、**客户端也走 IPv6**（两项均为 `true`）。模式与 YAML 双向同步；手写的其他组合显示「自定义」并说明原因，不自动改写。两个 IPv6 模式在 Fake-IP 模式下都补上缺失的 IPv6 Fake-IP 网段，并显示网段输入框，可直接自定义；选择「关闭」后收起输入框并保留值。和 IPv4 一样，两个 IPv6 模式都把这个网段发布到上游路由，在两者之间切换不用再改路由器。模式下方列出需要完成的步骤（主机准备、保存并发布、上游路由发布、路由器防火墙 / NAT、OxiDNS、验收），每步显示当前状态，有问题直接写原因并给出按钮或链接。点击**保存草稿**后设置窗口保持打开，并提示保存成功，步骤随即重新检查；点击步骤右上的**检查设备**打开独立检查窗口，结果仅显示 IPv6 网络、IPv6 节点连接、客户端分流三项；待验证时提示点击「验证连接与分流」或先配置检测客户端，不再展示逐条规则。ROS 对应路由在**上游路由 → 差异报告**中统一预览并发布，设备检查中的补齐仅处理主机配置。完整步骤与修改范围见 [IPv6 检查与准备](../ipv6-readiness.md)。

<a id="发布后验收"></a>
**发布后验收**：保存并发布成功后，如果这次发布的配置开启了 IPv6（两个 IPv6 模式），发布栏自动验收，并直接显示 IPv6 网络、IPv6 节点连接、客户端分流三项结果。「关闭」模式发布的配置没有 IPv6，发布栏只显示发布结果，不显示验收结果、「验证连接与分流」或「检查设备」提示。是否开启按这次发布的那一份配置判断，之后保存的草稿不影响。

![「关闭」模式发布成功后，发布栏只显示发布结果和上游路由提醒](../img/guide/mihomo-publish-ipv6-off.png)

**是否已发布只看 Mihomo 实际收到的文件**，与 Agent 页的同步状态用同一个比较，不看配置空间的版本号。发布上游路由会把路由记录写回同一配置空间，修改 OxiDNS 等其他服务的设置也会让版本号增加，但 Mihomo 的文件没变：「保存并发布 Mihomo」仍显示「已发布」，重新检查并点击「验证连接与分流」即可通过，不需要再发布一次 Mihomo。

![先发布 Mihomo、再发布上游路由后，步骤全部完成](../img/guide/mihomo-ipv6-steps-after-router.png)

![上游路由发布后重新检查并验证，三项结果通过](../img/guide/mihomo-ipv6-verify-after-router.png)

改了 Mihomo 的配置（例如规则、端口、DNS 或 IPv6 设置）并保存后，在重新发布前，「保存并发布 Mihomo」和验收的「IPv6 网络」都显示「待发布」。保存后服务端在后台比较文件，期间这一步短暂显示「核对中」。

![改了 Mihomo 配置并保存后，保存并发布 Mihomo 和验收都显示待发布](../img/guide/mihomo-ipv6-pending-after-change.png)

**订阅同步间隔**默认 3600 秒，可填 0 或 60–604800 的整数。它控制 Mihomo 定时从 ConfigFlow 同步订阅/聚合内容；0 表示仅手动同步。原始订阅是否重新下载仍受“订阅来源”的刷新间隔控制，这两项时间各自生效。通常先保持一小时，需要更快同步才缩短；改后要重新发布到设备。

1. 修改前记录原 YAML 和间隔，核对正在编辑的空间。
2. **保存草稿**保存到 ConfigFlow，在线核心继续使用原配置。
3. 要上线时明确选择“发布到”设备，再点 **保存并发布**。多个同类 Agent 共用一个空间时不要默认认为只影响当前看到的设备；发布目标需要明确核对。
4. 等发布与服务检查完成，返回面板刷新，再验证模式、代理选择和客户端访问。
5. 留空 YAML 并保存可恢复默认基础配置；这会替换当前空间的自定义基础草稿，需要保留自定义端口等参数时不要这样操作。

关闭尚未保存的编辑时按页面提示决定是否放弃。已保存但尚未发布的草稿，可重新改回再保存；已发布的错误内容按 [Agent 发布记录与回滚](agents.md#history)恢复，再把草稿修正，避免下一次又发出错误版本。

基础设置及 YAML 参数详见 [核心设置](core-settings.md)，完整生成、预览和发布步骤见 [配置生成](generate.md)。

<a id="troubleshooting"></a>
## 常见问题与回退

| 现象 | 检查顺序 |
| --- | --- |
| Agent 在线，Mihomo 面板打不开 | 核对核心是否运行、控制接口是否配置且可达、认证是否正确；查看核心日志。Agent 心跳正常只说明管理程序在线。 |
| 选了新节点，旧下载仍走旧出口 | 检查“切换节点时自动断开连接”是否关闭；旧连接可能保留。确认影响范围后断开相关连接，让客户端重连。 |
| 自动测速组不再自动切换 | 看是否标记“已固定”；用“取消固定/恢复自动”。 |
| 模式或节点选择后来变回去了 | 核对是否重载、重启、发布或其他管理端操作；运行时修改不等于改了 ConfigFlow 草稿。 |
| 加入规则集后，当前连接没变 | 确认规则集已启用、已完成同步/发布、命中顺序正确；再建立新连接。添加规则本身不会断开已有连接。 |
| 日志搜索不到旧错误 | 面板只读最近 500 行；暂停后及时查阅，需要更早记录时在设备的实际日志来源中查找。 |
| 更新后显示暂未恢复 | 等待后刷新版本和状态，查看 Agent/核心日志，避免连续重复更新；必要时按原部署方式恢复核心。 |

只想查看状态时用“刷新”；想改变在线出口时用模式/策略；想永久修改生成内容时走设置与发布。操作前先分清这三个范围。
