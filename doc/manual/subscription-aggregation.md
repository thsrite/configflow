# 订阅聚合：把多个来源组织成一个可复用节点集合

本页目录：[什么时候用](#什么时候用) · [先做一次](#先做一次) · [表单和按钮](#表单和按钮) · [过滤与去重的真实范围](#过滤与去重的真实范围) · [保存与备份](#保存与备份)

入口：**共享资源 → 订阅聚合**。没有这个菜单时，先在「系统设置 → 常规 → 服务配置」打开「订阅聚合」。这个开关控制入口显示；要让节点真正被使用，还需在策略组里引用聚合。

## 什么时候用

你有两个订阅和几个自建节点，希望多个配置空间都能选同一组“香港节点”，可以建立一个聚合。之后在多个策略组里引用它，不必反复挑来源。

聚合保存的是“取哪些订阅、哪些节点、怎样过滤”的关系，不是把全部节点复制成互不关联的新记录。来源更新后，后续生成的聚合内容也会变化；修改共享聚合会影响所有引用它的配置。

## 先做一次

1. 先在 [订阅来源](subscriptions.md) 手动更新一次要使用的订阅，确认缓存有节点；独立节点先在 [节点库](nodes.md) 添加。
2. 点「添加聚合」，填名称，例如“家庭常用”。
3. 选择至少一个订阅或节点，第一次先不填正则过滤。
4. 保持启用并保存，点「预览节点」，检查合并结果。
5. 到 [策略组](proxy-groups.md)，勾选「订阅聚合」来源并选择此聚合，保存后再生成配置。

## 表单和按钮

| 选项／按钮 | 用途与推荐；开启／关闭结果 |
| --- | --- |
| 聚合名称 | 在策略组里识别集合。使用清晰名称，不要以为与另一个聚合同名就会自动合并。 |
| 选择订阅 | 合入这些订阅提供的节点；通常只选日常确实要使用的来源。列表正常提供已启用来源，停用来源不会因此被强制启用。 |
| 选择节点 | 再加入独立节点；不必为了加入一个自建节点新建订阅。 |
| 多选框的全选／取消全选 | 快速选择当前选项或搜索结果；检查数量再保存，避免不小心把所有来源都加入。 |
| 正则过滤 | 对合并后的节点名称做保留筛选；留空保留候选节点。例如 `香港\|HK`。这会影响所有使用此聚合的配置；仅某个策略组需要额外筛选时，在那个组里设置。 |
| 健康检查 | 生成给核心的来源级检测，字段与 [订阅来源健康检查](subscriptions.md#健康检查) 相同。新建默认启用、300 秒、5 秒超时、懒惰检测、预期 204。它不决定服务商订阅多久更新。 |
| 引用配置 | 展示哪些配置空间使用此聚合，帮助判断修改会影响谁。 |
| 描述 | 只用于说明用途，留空不影响节点连接。 |
| 聚合启用中／聚合已停用 | 开启后可被策略组选择；关闭后不再出现在正常来源选择中。已有使用者需核对是否变成空组；不会把被聚合的原订阅或独立节点一并删除。 |
| 保存／取消 | 保存共享集合规则，或放弃本次未保存修改。 |
| 预览节点 | 生成当前集合的预览，可查看订阅统计与单个节点内容；可能需要拉取来源，并非对设备做连通性测试。 |
| 订阅统计中的来源项 | 只读该订阅已保存的节点缓存，应用订阅自身的筛选；不会访问上游，也不会修改拉取时间或运行记录，包括设为「仅手动」时。聚合过滤前后、去重前后的数量可能不同。 |
| 编辑、启用／停用 | 修改共享聚合，不会立即向所有设备推送新配置。 |
| 调整顺序 | 调整聚合列表展示，保存后生效；不代表修改网络中节点的延迟优先级。 |
| 删除 | 被配置使用时需要先解除引用。删除聚合本身不等于删除原订阅与节点；仍须重新生成受影响配置。 |

查看单个来源时，缓存过期也不会自动重新下载。没有缓存，或订阅地址已变更、原缓存不再适用时，窗口会提示先到「订阅来源」手动拉取；拉取后重新打开即可查看。读取缓存失败会单独显示错误，不会改用上游请求。

## 过滤与去重的真实范围

筛选顺序可以这样理解：**订阅自身的筛选 → 聚合的筛选 → 策略组自己的保留／排除筛选**。前面已经去掉的节点，后面的筛选不能把它找回来。

当前聚合在追加手动节点时，会按节点名称跳过集合里已有的同名项。不要把它理解为“自动比较服务器、端口、密码并去重所有订阅”：多个订阅之间没有统一的连接信息去重保证。同名不同节点应先改成可区分的名字；同一连接不同名字也不能保证被合并。

卡片数量可由已有订阅缓存与所选节点计算，未必等于最终经过正则过滤后的结果。修改后以「预览节点」和实际生成结果核对，不要为了凑数量重复添加来源。

## 保存与备份

聚合保存的是共享资源关系；运行中的设备要等下一次读取来源或重新发布才使用新结果。来源坏了而仍有缓存时，预览可能使用旧节点；没有可用内容时应处理来源错误，不能靠重复保存聚合修好。

完整数据导出可备份聚合及其共享资源。只导出一个配置空间时，不应假定随附了全部订阅、独立节点和缓存；迁移先保存全部数据并按部署指南备份整个数据目录。聚合预览或复制节点内容是查看结果，不是完整备份。
